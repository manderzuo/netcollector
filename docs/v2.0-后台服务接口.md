# v2.0 本地后台服务接口（M2-1）

## 目标

把耗时的任务调度、浏览器操作和数据库状态从界面进程中分离出来。当前先提供
兼容层和集成测试，不改变现有 `src/gui.py` 的启动入口；后续 Tk 和 QML 界面
都通过同一套接口接入。

## 运行边界

- 服务只监听 `127.0.0.1`、`localhost` 或 `::1`，不开放局域网端口。
- 每次服务启动生成随机令牌，地址文件只保存本机连接所需信息。
- 服务端持有 `Scheduler`；客户端不能调用任意 Python 方法。
- 数据库仍是任务状态真源，服务重启或 GUI 重连都以数据库快照为准。
- 真实发送、验证码处理和浏览器操作仍遵守现有人工确认规则。

## 消息格式

使用 UTF-8 JSON Lines，一行一条消息，协议版本为 `1`。

### GUI → 服务：命令

```json
{"protocol":1,"kind":"command","request_id":"...","command":"status","args":{},"token":"..."}
```

### 服务 → GUI：应答

```json
{"protocol":1,"kind":"response","request_id":"...","ok":true,"result":{}}
```

失败时：

```json
{"protocol":1,"kind":"response","request_id":"...","ok":false,"error":{"code":"...","message":"..."}}
```

### 服务 → GUI：事件

```json
{"protocol":1,"kind":"event","event":"state_snapshot","sequence":1,"payload":{}}
```

目前的事件类型：

- `state_snapshot`：任务、账号和汇总状态发生变化时推送。
- `log`：后台产生一条运行日志时推送。
- `backend_error`：后台状态快照读取异常时推送。

## 第一版白名单命令

`status`、`get_task`、`create_task`、`start`、`pause`、`resume`、`stop_task`、
`delete_task`、`add_account`、`remove_account`、`resolve_human`、
`waiting_accounts`、`configure_monitoring`、`start_monitoring`、
`stop_monitoring`、`run_monitoring_once`。

任务状态报表通过 JSON 传输后，`tasks` 对象的任务编号是字符串键；这是 JSON
对象键的标准行为，不改变数据库中的整数任务 ID。

## 已完成验证

- 协议编码、解码和未知命令拒绝。
- 地址文件原子写入、读取和临时文件清理。
- 本地服务握手与随机令牌校验。
- 状态快照事件推送。
- 任务创建、暂停、继续、启动和 FakeCollector 完成闭环。
- 客户端在 Windows 下安全关闭和重连，不阻塞测试收尾。

3. 用独立后台进程启动服务，并增加 GUI 断线重连和服务恢复提示。
4. 新建 PySide6/QML 外壳，逐页复用同一服务接口。
