# 代码更新方案

## 目标

员工只需要使用代码更新包，就能把旧版本替换为新版本，不需要重新添加账号、窗口、LLM 或采集数据。

## 更新包包含

- src：程序代码和界面逻辑
- assets：软件与平台图标等界面资源
- lib：项目使用的代码库
- VERSION.txt
- requirements.txt、requirements-v2.txt
- monitor_gui.ps1

## 明确不包含、不覆盖

- data：账号、窗口 ID、任务、线索、互动、LLM 配置、缓存和数据库
- config：服务地址、更新配置以及用户配置
- .venv：员工本机运行环境
- logs、exports、temp
- 任何 .db、.db-wal、.db-shm 文件

## 员工操作

1. 退出软件 GUI；如果正在采集，先按业务要求暂停。
2. 将 collector-code-update-vX.Y.zip 解压到旧程序目录，选择合并文件。
3. 双击包内的 apply_code_update.bat。
4. 更新器先校验清单和 SHA-256，再覆盖代码；完成后重新双击原来的启动器。

更新失败会自动恢复本次已经替换的代码。每次更新前的代码会保存在旧程序目录的 code_backups 中。

## 开发者生成更新包

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build_code_update.ps1
~~~

输出的 ZIP 就是交给员工的代码更新包。发布前应检查 ZIP 内容中没有 data、config、.venv、logs、exports 或数据库文件。

## 安全边界

更新器只接受 src、assets、lib 和少量根目录运行文件；即使更新包被误放入其他目录，也不会根据包内容删除或覆盖受保护的数据目录。
