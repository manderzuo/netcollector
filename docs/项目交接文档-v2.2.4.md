# 多平台采集工作台项目交接文档

## 1. 交接结论

- 当前版本：`2.2.4`
- 构建号：`20260911-2.2.4-runtime-bootstrap-v1`
- 代码仓库：<https://github.com/manderzuo/netcollector>
- 当前开发分支：`codex/ui-polish-2.2`
- 本次目标：修复其他电脑首次启动闪退、旧启动器抢占、虚拟环境缺少 pip/PySide6、更新后无法启动等问题，并保留用户数据。

本版本的默认入口是 PySide6/QML 工作台：

```text
start.bat
  -> launcher.ps1
    -> runtime_bootstrap.ps1
      -> src/ui2/default_app.py
```

旧版 `src/gui.py` 仍保留，只有显式使用监控脚本的 `-Legacy` 参数时才会进入旧 Tk 界面。

## 2. 本次修复内容

### 2.1 启动与运行环境

1. 新增 `runtime_bootstrap.ps1`，启动前检查 PySide6 是否可导入。
2. 旧 `.venv` 存在但缺少 pip 时，先通过 `ensurepip` 修复，再安装 `requirements.txt`。
3. 旧环境修复失败时，自动使用系统 Python 创建独立的 `.runtime`，避免破坏已有 `.venv`。
4. 启动器优先使用能成功导入 PySide6 的 Python，不再仅凭 `python.exe` 文件存在就启动。
5. `start.bat`、`launcher.ps1`、`install_environment.ps1` 统一进入 QML 默认界面。
6. 解决 Windows PowerShell 读取 `requirements-v2.txt` 时因中文注释和系统编码导致的解码失败；文件改为 ASCII 注释。

### 2.2 更新与重启

1. 版本从 `2.2.3` 提升到 `2.2.4`，避免相同版本号被客户端判定为无需更新。
2. 代码更新包包含 QML 入口、运行时引导、监控脚本、启动器和依赖文件。
3. 更新后会再次检查 PySide6，确认运行时可用后才进入重启阶段。
4. 更新重启优先拉起 QML 入口；仅在新入口不存在时才使用兼容回退。
5. 正式包内的根目录更新器、便携更新器两个脚本副本统一构建，避免从不同入口更新出现行为差异。
6. 更新过程继续保护用户目录：`data`、`config`、`.venv`、`.runtime`、`logs`。

### 2.3 卡死监控

`monitor_gui.ps1` 默认监控 QML 入口，读取 `data/gui_heartbeat.txt`：

- QML 主线程每秒更新心跳；连续超过默认 15 秒不更新，记录疑似卡死。
- 记录进程存活、主线程 CPU 时间、线程数、数据库大小和最近写入时间。
- 默认只告警；需要自动拉起时使用 `-AutoRestart`。
- 需要结束卡死进程并重启时使用 `-AutoRestart -KillHung`。
- 需要监控旧 Tk 界面时显式加 `-Legacy`。

示例：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\monitor_gui.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\monitor_gui.ps1 -AutoRestart
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\monitor_gui.ps1 -AutoRestart -KillHung -HungSeconds 30
```

日志位置：`data/gui_monitor.log`；运行时依赖日志：`logs/runtime_bootstrap.log`。

## 3. 目录与数据边界

| 路径 | 用途 | 更新时处理 |
| --- | --- | --- |
| `src/` | Python 后台、采集器、QML 桥接 | 替换 |
| `assets/`、`lib/` | 界面资源和前端库 | 替换 |
| `data/` | 数据库、账号绑定、任务、心跳和运行端点 | 保留 |
| `config/` | 更新配置和本地配置 | 保留 |
| `logs/` | 更新、监控、运行日志 | 保留 |
| `.venv/` | 旧版用户虚拟环境 | 保留，必要时修复 |
| `.runtime/` | 2.2.4 自动维护的独立虚拟环境 | 保留，必要时修复 |
| `runtime/` | 免安装 EXE 包的内置运行时 | 仅随 EXE 包使用 |

原则：不能为了安装依赖删除 `data`、`config`、`.venv`、`.runtime` 或 `logs`。用户账号、任务和采集结果均在这些目录中。

## 4. 依赖与首次启动

`requirements.txt` 当前包含：

```text
customtkinter==6.0.0
websockets>=12.0
Pillow>=10.0
tzdata>=2024.1
PySide6>=6.7,<7
```

在本机实测，首次创建环境并安装全部依赖约 2 分钟，下载约 255 MB，安装后环境约 681 MB；实际时间取决于网络和电脑速度。安装完成后，后续启动不再重复下载。

如果电脑没有可用 Python 3.11 或网络受限，自动引导会写明原因并停止，不会删除用户数据。此时应准备离线 wheel 缓存或把已验证的 `.runtime` 复制到目标机器。

## 7. 发布与回滚

### 发布

1. 确认 Git 分支、版本号、构建号和两个 zip 的 SHA256。
2. 在线 release 目录先建立带时间戳的备份目录。
3. 上传正式包、代码更新包和 `latest.json`。
4. 用浏览器或请求检查清单和两个 zip 均返回 HTTP 200。
5. 下载后重新计算 SHA256，与 `latest.json` 一致。
6. 在一台已有 2.2.3 数据的机器上先执行代码更新，确认数据、账号、任务和重启均正常，再扩大推送范围。

### 回滚

- 线上回滚：恢复发布前备份的 zip 和 `latest.json`。
- 客户端代码回滚：使用应用目录下 `code_backups/<时间戳>/` 中的代码备份，先关闭 GUI，再恢复对应版本文件。
- 运行时问题：保留 `.venv`，检查 `logs/runtime_bootstrap.log`；必要时删除仅由 2.2.4 创建的 `.runtime` 后重新引导。删除前必须确认其中没有用户手工安装的内容。

## 8. 常见排障

### 双击闪退，没有窗口

1. 从 PowerShell 执行 `start.bat`，不要只看双击结果。
2. 查看 `logs/runtime_bootstrap.log`。
3. 确认 `src/ui2/default_app.py`、`src/ui2/qml/main.qml` 和 `runtime_bootstrap.ps1` 存在。
4. 执行：

```powershell
.\runtime_bootstrap.ps1
```

实际使用时应通过 `launcher.ps1` 或 `install_environment.ps1` 调用其中的函数；引导脚本本身只提供函数，不直接打开窗口。

### 提示没有 pip 或没有 PySide6

```powershell
py -3.11 -m ensurepip --upgrade
py -3.11 -m pip install --disable-pip-version-check --no-input -r requirements.txt
```

不要把 `--disable-pip-version-check` 传给 `ensurepip`；它是 pip 的参数。

### 更新完成但没有重启

查看 `logs/update.log`，确认是否出现 `restart_started`；同时查看 `logs/runtime_bootstrap.log` 是否在 PySide6 检查阶段失败。若旧安装只有 `src/gui.py` 而没有新启动器，先使用完整包更新一次。

### 界面卡死

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\monitor_gui.ps1 -AutoRestart -KillHung
```

保留 `data/gui_monitor.log`、`logs/runtime_bootstrap.log`、`logs/update.log` 和发生问题时的任务截图，便于判断是 Qt 主线程、后台服务、浏览器响应还是外部人工验证导致。

## 9. 后续建议

1. 在发布服务器增加 wheel 缓存或提供离线依赖包，减少目标电脑首次安装的不确定性。
2. 将外部进程测试统一改成可回收的测试夹具，禁止测试启动无法追踪的常驻进程。
3. 将“贴吧平台已支持”的平台集合抽成共享测试常量，避免实现和旧断言再次漂移。
4. 在线上灰度机器验证更新进度窗口、自动重启和大批量评论采集场景后，再扩大到全部客户端。
