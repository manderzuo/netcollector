# 多平台采集工作台 V2.1.1 更新说明

发布日期：2026-09-03

## 版本定位

V2.1.1 是 V2.1 的兼容性维护版，继续使用新版 QML 工作台作为默认入口，保留原有采集、任务、账号、线索、互动、发布、诊断、日志和导出能力。

## 本次更新

- 统一版本号来源：界面标题、侧栏版本、后台设备登记和发布清单统一读取 `VERSION.txt`，避免显示版本与实际包版本不一致。
- 稳定私信模拟流程：按平台和目标主页选择浏览器页面，排除比特浏览器控制台及创作者页；每次执行前复核页面状态，重新查询私信按钮和输入框，填入后再次核对内容。
- 增加页面稳定探测、按钮稳定探测、输入框状态探测和失败阶段记录；仅在发送前的可恢复定位失败时有限重试，不重复执行已经点击发送的动作。
- 账号主页内容标题清洗：平台未提供标题或返回作品编号/统计数字时显示“未命名内容”，不再把数字误显示为标题。
- 发布内容填入后按页面实际长度进行比对，避免长标题已经成功填入却被误判为失败。
- 定时发布使用北京时间，保存授权状态和执行结果；发布任务及未确认原因会落库并写入操作日志，重启后台后可继续处理到期任务。
- 定时发布时间选择改为日历弹窗，禁止选择过去的日期和时间，并修复发布设置区域内容被裁切的问题。
- 发布中心和账号信息页面继续保留平台版本编辑、媒体预览、真实发布开关及账号隔离逻辑。
- 新增统一账号服务器链路：员工注册申请通过 `https://www.gemstory.cn` 提交，管理员可在任意设备的个人中心查看并审批，审批状态会回传员工端；员工本机仍只保留自己的数据、账号绑定和浏览器登录态。
- 修复跨设备注册审批不可见的问题：不再只写入注册电脑的本地数据库，远程注册、登录、审批、禁用和密码重置使用统一认证服务；服务不可用时，既有本地账号仍可按原逻辑登录。
- 修复自动更新只比较版本号的问题：同一版本的修复包也会通过构建标识被识别。
- 设置与诊断页新增“检查更新”和“立即更新并重启”，检查过程不阻塞界面，更新时保留本地数据、账号和 LLM 配置。
- 更新清单请求增加缓存规避和阶段日志；旧包即使没有构建标识，也能识别当前线上修复包。

## 数据与升级安全

- 干净正式包不包含本机数据库、账号绑定、BitBrowser 窗口 ID、浏览器登录态、Cookie、API Key、导出文件、运行日志或虚拟环境。
- 员工电脑应使用代码更新包升级；更新器只覆盖 `src`、`assets`、`lib` 和运行脚本，不覆盖 `data`、`config`、`.venv`，原有账号、窗口、采集结果和 LLM 配置保留。
- 更新前自动生成代码备份，更新校验失败会回滚本次覆盖的代码文件。

## 启动方式

首次使用：双击“安装环境并启动.bat”。

日常使用：双击“启动器.bat”。

需要持续监控时：运行 `monitor_gui.ps1 -AutoRestart -Quiet`。

当前默认版本：`2.1.1`。
