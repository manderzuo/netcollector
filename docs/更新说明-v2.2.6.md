# 多平台采集工作台 V2.2.6 更新说明

发布日期：2026-09-17

## 本次更新

- 修复部分 Windows PowerShell 5.1 电脑缺少 PySide6 时，运行时检测被 Python `Traceback` 中断、无法进入自动修复的问题。
- PySide6 和 pip 探测现在会安全捕获原生进程错误；若包内存在 wheel 缓存，优先使用本地依赖安装，失败后再尝试联网安装。
- 优化任务中心和采集总览的大批量任务状态刷新，减少界面拖动、切换页面和切换任务状态时的卡顿。
- 修复采集中进度广播触发所有 QML 页面重算的问题；开始、暂停、继续、停止现在立即反馈并锁定当前任务，避免重复点击叠加控制命令。
- 展示状态轮询改用短时缓存，停止任务的多账号线程等待改为整次最多 3 秒，降低控制按钮的响应延迟。
- 将评论采集后的意向分析统一改为批量提交；即使未启用 LLM，也按批次处理评论，避免逐条处理造成队列堆积。
- 优化评论补全、楼中楼和意向分析队列的收尾与退出流程，减少大量评论采集时后台阻塞和关闭不完整。
- 修复抖音大评论区因短暂无新响应就提前结束的问题：改为分段滚动、边接收边读取响应体，并结合 `has_more`、页面到底和待处理响应判断结束。
- 修复评论响应体过期导致的少采/漏采；单作品允许更长的分页窗口，CDP 超时会带具体阶段信息并自动重建连接重试当前作品。
- 修复高评论量下线索扩展长事务造成的 `database is locked`，改为小批量写入、锁冲突退避重试；监控任务等待账号时不再每 15 秒重复触发。
- 优化调度器状态汇总、日志写入和账号状态巡检，降低高频数据库查询与日志 I/O 对采集任务的影响。
- 优化监控采集运行记录的收尾，确保监控任务每轮运行都能及时更新状态。
- 延续 V2.2.5 的小红书、B 站、微博楼中楼回复定位修复，以及小红书风控降频处理。

## 升级说明

代码更新包会保留用户现有的 `data`、`config`、`.venv`、`.runtime` 和 `logs`；升级前建议关闭正在运行的采集任务，并保留现场日志。

如果升级后仍出现界面无响应，请同时保留 `data/gui_monitor.log`、`logs/update.log`、`logs/runtime_bootstrap.log` 和对应任务截图。
