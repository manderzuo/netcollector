# 多平台采集工作台 v1.2—v2.0 优化实施方案

> 范围：暂不增加采集平台，继续维护抖音、小红书、B站、微博。
>
> 原则：第一阶段先稳定底层和补齐实用能力；第二阶段再迁移界面、完善线索运营和数据分析。真实回复继续默认关闭，所有人工验证保留人工处理。

## 一、最终目标

把当前应用从“采集程序加业务页面”升级为由以下三层组成的桌面工作台：

1. 桌面界面：只负责展示、筛选和下达操作，不直接执行耗时采集。
2. 本地任务服务：统一调度搜索、详情、评论、验证、暂停、继续和回复任务。
3. 平台适配器：抖音、小红书、B站、微博分别处理自身页面差异。

第一阶段结束后，重点得到“稳定、可恢复、可监控”；第二阶段结束后，重点得到“漂亮、流畅、适合日常运营”。

## 二、第一阶段：底层稳定与实用能力（建议版本 v1.2）

### 1. 冻结现有流程并建立回归基线

#### 工作内容

- 固定四个平台现有搜索、滚动加载、详情采集、评论采集和回复框填入行为。
- 把真实浏览器验证过的关键流程整理为平台回归用例。
- 建立脱敏测试数据，不在发布包中保留个人账号、评论和浏览器窗口 ID。
- 为每次采集和回复分配唯一运行编号，日志、截图和错误信息按编号归档。

#### 验收标准

- 四个平台模拟回复仍然只填入、不发送。
- 采集暂停、程序重启、人工验证后都能从明确节点继续。
- 任意失败可以根据运行编号查到完整操作时间线。

### 2. GUI 与采集任务彻底分离

#### 工作内容

- 将采集调度器从 GUI 主进程移入独立后台服务。
- GUI 通过本地消息接口接收任务状态和增量数据，不再直接等待浏览器、网络或数据库。
- 账号、平台分别使用独立执行队列；单个浏览器超时不能卡住其它任务和界面。
- GUI 重启后重新连接后台服务，显示原任务真实状态。
- 建立统一任务状态机：等待、搜索中、采集详情、采集评论、需要人工、暂停、暂无更多、完成、失败。
- 状态改变采用事件推送；无事件时界面不反复查询和重绘。

#### 验收标准

- 采集运行时拖动、缩放和切换页面不受浏览器操作影响。
- 一个账号进入人工验证时，其它账号按规则继续工作。
- 暂停只停止新操作，正在等待的页面操作可安全结束，不产生错误超时记录。

### 3. 断点、去重与增量监控

#### 工作内容

- 每次任务记录搜索位置、已发现作品、已完成详情、已完成评论及结束原因。
- 作品按“平台＋作品 ID”去重；评论按“平台＋作品 ID＋评论 ID”去重。
- 没有稳定评论 ID 时使用规范化昵称、纯文字评论、评论时间组成备用指纹。
- 重复内容不计入新增数量，也不能被误判为“页面没有加载新内容”。
- 增加“增量监控任务”：一次、每天、指定间隔、指定工作时段。
- 增量任务只写入新作品和新评论，并展示本轮发现、去重、新增、失败数量。
- “暂无更多视频”只表示本轮到达终点；用户可以点击继续采集，后续发现新内容时自动补入。

#### 新增界面

- 新建任务增加“执行方式”：单次采集、定时增量监控。
- 任务详情增加“本轮结果”和“历史运行记录”。
- 任务列表增加下次运行时间、最后结束原因、连续失败次数。

### 4. 关键词组

#### 工作内容

- 支持一个任务引用一个关键词组。
- 关键词组包含：核心词、同义词、地域词、排除词。
- 新建任务时可以预览最终搜索组合，并手动取消某个组合。
- 统计每个关键词带来的作品数、评论数、有效线索数和回复数。
- 关键词组版本化；修改后不改变历史任务当时使用的规则。

#### 示例

- 核心词：幼儿园、托班、早教。
- 地域词：郑州、洛阳。
- 排除词：招聘、求职、转让。

### 5. 用户去重与历史轨迹

#### 工作内容

- 同平台优先用平台用户 ID 合并；没有 ID 时使用主页地址或稳定账号标识。
- 昵称只能作为辅助信息，不能单独作为合并依据。
- 不自动跨平台合并用户；允许人工确认“这是同一个人”。
- 保存用户首次出现、最近出现、关联任务、评论记录、互动记录和跟进记录。
- 采集证据不删除，用户主档与原始评论保持关联。

#### 验收标准

- 同一个用户在多个任务重复出现时，线索中心只显示一个用户主档，并能展开全部评论。
- 合并和拆分操作有审计记录，可撤销。

### 6. 可解释的线索评分

#### 工作内容

- 第一阶段采用可配置规则评分，不依赖 AI。
- 可配置维度：购买/咨询关键词、地区命中、问题明确度、重复互动、联系方式倾向、负面词和无效词。
- 每条线索展示总分、评分等级和加减分原因。
- 人工可以修改分数和意向标签。
- 评分只用于排序、筛选和提示，不能阻止人工加入互动中心。

#### 验收标准

- 用户可以回答“为什么是 88 分”。
- 修改评分规则后可选择只影响新数据，或对历史线索重新计算。

### 7. 账号安全控制与人工验证

#### 工作内容

- 每个账号可设置每日采集上限、每小时回复上限、操作间隔、工作时段和连续失败暂停值。
- 出现验证码、登录失效、页面灰化、滚动无变化时进入“需要人工”状态。
- 验证完成后继续使用原任务绑定账号，不得自动切换账号。
- 真实发送保持每次启动默认关闭；批量期间关闭后立即阻止后续真实发送。
- 勿扰、黑名单和频率限制在真实发送前最后校验，不能被旧界面状态绕过。

### 8. 平台健康检测与诊断中心

#### 工作内容

- 四个平台分别提供健康探针：登录状态、搜索区、评论区、滚动容器、回复按钮、输入框。
- 记录选择器版本和最后成功时间。
- 连续定位失败时保存当前网址、页面截图、关键 DOM 摘要和滚动信息。
- 诊断中心按平台展示：正常、需要登录、疑似页面改版、人工验证、接口异常。
- 支持一键导出脱敏诊断包。

### 9. 数据库、备份与迁移

#### 工作内容

- SQLite 开启 WAL，补齐高频查询索引，所有写入经过统一写队列。
- 新增数据表：监控规则、关键词组、任务运行、任务事件、用户身份、评分记录、账号限制、健康事件、备份记录。
- 每日自动备份，升级前强制生成升级备份。
- 提供一键备份、一键恢复、迁移到新电脑和数据完整性检查。
- 更新程序只替换程序文件，不覆盖个人数据库、配置、模板和日志。

### 10. 第一阶段测试门槛

- 单元测试：状态机、去重、评分、关键词组合、账号限制。
- 集成测试：暂停继续、程序重启、验证码恢复、暂无更多后继续采集。
- 平台回归：四平台搜索、评论懒加载、模拟回复。
- 性能测试：后台采集时连续切换页面、拖动窗口、缩放窗口。
- 数据测试：旧版本数据库升级、备份恢复、重复导入。

### 第一阶段建议顺序

1. 回归基线与运行编号。
2. 后台任务服务和状态机。
3. 断点、去重和增量监控。
4. 用户主档、关键词组和规则评分。
5. 账号安全、平台健康和诊断中心。
6. 备份迁移、界面接入和完整回归。

## 三、第二阶段：新界面与线索运营（建议版本 v2.0）

### 1. PySide6＋Qt Quick/QML 界面迁移

#### 迁移原则

- 保留第一阶段完成的后台服务、平台适配器和数据库。
- 新旧界面短期共用同一服务接口，按页面逐步替换。
- 先迁移应用外壳和高频页面，再迁移设置类页面。
- 不在迁移期间修改平台采集规则，避免同时引入两类风险。

#### 页面迁移顺序

1. 应用外壳、导航、通知和全局搜索。
2. 任务中心和账号管理。
3. 线索中心。
4. 互动中心。
5. 采集总览、数据分析、设置与诊断。

#### 性能方案

- 页面首次打开后常驻，不重复销毁和创建。
- 表格和卡片使用 Model/View 与行复用，只渲染当前可见内容。
- 数据查询、图片解码、导出和 AI 请求全部在后台执行。
- 筛选输入采用短延迟合并，查询完成前保留旧内容并显示局部加载状态。
- 高频状态只更新变化字段，不整页刷新。
- 支持 Windows 高分屏、原生边框、键盘操作和 SVG 矢量图标。

### 2. 新版信息架构

#### 采集总览

- 今日新增作品、评论、有效线索、待回复和回复率。
- 从作品到回复的转化漏斗。
- 正在运行的增量任务、需要人工处理的账号和平台健康状态。
- 最近异常及快速处理入口。

#### 任务中心

- 单次任务与增量监控分组。
- 任务行直接显示当前阶段、本轮新增、目标数量、账号和结束原因。
- 右侧详情展示每次运行历史、去重结果和错误时间线。
- 支持保存任务配置并复制创建新任务。

#### 线索中心

- 主表格＋右侧详情抽屉。
- 主表格显示用户、评论原文、时间、评分、状态；长文本最多两行。
- 右侧展示评分原因、AI摘要、全部评论、来源任务和用户轨迹。
- 支持保存筛选视图、批量打标签、批量加入互动中心和设置跟进。

#### 互动中心

- 保留待生成、待发送、已回复、失败四个主要状态。
- 回复编辑区固定展示原评论、完整模板、变量结果和最终发送内容。
- 失败项展示失败原因、运行编号、截图入口、退回待生成和删除。
- 批量回复按平台和账号自动分组，执行前展示预计数量和账号限制。

#### 数据分析

- 作品→评论→线索→互动→回复的转化漏斗。
- 按平台、任务、关键词、账号、模板和日期比较。
- 统计重复率、有效线索率、模拟成功率、真实发送成功率和回复率。

### 3. 跟进与提醒

#### 工作内容

- 用户状态：新线索、待联系、已联系、等待回复、二次跟进、已成交、无效。
- 支持负责人、下次跟进时间、备注和提醒。
- 用户详情显示完整操作时间线。
- 到期提醒进入通知中心；支持稍后提醒、完成和重新安排。
- 互动中心完成回复后，可直接创建下一次跟进。

### 4. AI 分类、摘要与回复辅助

#### 工作内容

- 自动识别价格、地址、课程、合作、投诉、闲聊等意图。
- 对一个用户的多条评论生成线索摘要。
- 根据评论原文、用户轨迹和模板生成完整回复建议。
- 提供简洁、自然、正式等不同语气，但最终内容始终可编辑。
- AI结果展示依据和置信度；低置信度进入人工确认。
- AI功能可关闭；未明确授权时不向外部模型发送个人数据。

#### 与第一阶段评分的关系

- 规则评分继续保留，作为稳定基线。
- AI只提供分类、摘要和附加分，不直接决定是否可以互动或发送。

### 5. 模板管理与效果统计

#### 工作内容

- 模板支持分类、平台、适用意图、自定义中文变量和版本记录。
- 修改模板不会改变历史已经发送的内容。
- 同一场景可建立 A/B 版本，并按设定比例推荐。
- 统计每个模板的使用量、填入成功率、发送成功率、回复率和平均回复时间。
- 样本过少时只显示数据，不给出“优胜模板”结论。

### 6. 全局搜索、保存视图和批量操作

- 全局搜索用户昵称、评论、作品地址、任务和运行编号。
- 线索、任务和已回复列表可以保存常用筛选条件。
- 批量操作使用固定工具条，明确显示选择数量和影响范围。
- 删除、合并和状态改变支持撤销或二次确认。
- 页面切换后保留滚动位置、筛选条件、分页和勾选状态。

### 7. 第二阶段验收门槛

- 采集运行时切换页面视觉响应不超过 100 毫秒，不出现整页空白。
- 1 万条线索条件下，滚动和选择保持流畅。
- 调整窗口大小时列表连续重排，不冻结后突然跳变。
- 任何页面不得同步等待浏览器、数据库、导出或 AI 请求。
- 四平台现有采集与回复契约全部通过，数据库升级可回滚。
- 新旧界面关键统计结果一致后，才移除旧 GUI。

## 四、界面视觉方向

- 采用深色高密度工作台风格，主色继续使用蓝色。
- 左侧导航保持稳定，主工作区采用指标、筛选、表格和右侧详情四层结构。
- 减少巨大卡片和大面积空白，用细边框、轻层级和状态色区分信息。
- 评论原文保留两行；完整内容在右侧详情查看。
- 平台图标统一使用高清 SVG，不在运行时重复缩放位图。
- 错误、人工验证和真实发送使用独立警示色，普通状态不滥用彩色。

## 五、范围控制

本轮明确不做：

- 不增加第五个平台。
- 不绕过平台验证码或反自动化机制。
- 不在第一阶段整体重写 GUI。
- 不让 AI 自动决定真实发送。
- 不在没有备份和迁移测试前改变用户数据库格式。

第一阶段应先证明后台服务稳定、任务可以恢复、数据能够去重；达到门槛后再开始第二阶段界面迁移。
