# v1.2 升级执行进度

更新时间：2026-08-27

本文只记录已经落地并通过代码测试的内容，不把设计目标写成已完成能力。

## 已完成

### GUI 卡死修复（2026-08-27）

- 修复状态轮询每轮创建短命线程、以及后台线程直接调用 Tk `root.after` 导致的线程堆积。
- 改为单一状态刷新线程、刷新请求合并和最新报表覆盖；界面回调统一进入有上限的主线程队列。
- 日志展示、窗口操作、任务操作和诊断反馈均不再从后台线程直接触碰 Tk。
- 监控实测旧进程线程数曾增长到 1550+；修复后新进程启动线程数为 5，连续观察 30 秒保持稳定。
- 增加 GUI 刷新生命周期回归测试；不修改数据库、任务状态和用户配置。

### TAB 切换重绘优化（2026-08-27）

- 主页面启动时统一挂入层叠容器，左侧 TAB 切换只提升目标页面，不再反复卸载和挂回整棵控件树。
- 启动阶段提前清空 Tk 的首轮布局和画布重绘队列，避免首次切换时出现从底部向上的补绘效果。
- 启动阶段提前完成首轮布局和画布重绘；运行期间 TAB 切换只执行页面提升，并记录 `lift_ms` 供后续排查。
- 点击/滚轮审计日志改为后台顺序落盘，保留完整操作记录但不阻塞 TAB 切换。
- Windows 原生拖动/缩放冻结逻辑保持不变，页面仍使用相对尺寸跟随窗口。

### 可观测性与任务运行记录

- 新增 `collection_runs` 和 `collection_events`。
- 每次任务启动/继续都会生成运行编号，记录搜索、补采、人工验证、停止和终态。
- 任务报表增加最近一次运行记录和监控规则摘要。
- 修复任务启动时局部 `json` 导入遮蔽全局模块的问题，避免任务绑定账号被忽略而误选其它账号。

### 增量监控

- 新增 `monitoring_rules`。
- 新建任务支持“单次采集 / 定时增量监控”。
- 监控间隔可配置，范围为 60 秒至 7 天，默认 3600 秒。
- GUI 启动时恢复监控后台；正在运行的任务不会重复触发。
- 明确记录“暂无更多内容”的运行不会被后台无限重启；手动继续仍可重新打开搜索闸门。
- 任务中心列表新增“监控设置/增量监控”按钮，可按任务单独启用或停用定时增量监控。
- 设置弹窗支持按小时和分钟填写间隔，并按平台默认选择“最新”排序：抖音/小红书使用最新，微博使用实时，B站使用最新发布。
- 重新保存任务的监控设置会清除旧的“暂无更多内容”闸门，避免规则已启用但任务仍被旧终止状态拦截。

### 关键词组

- 新增核心词、同义词、地域词、排除词的数据表和预制搜索词展开服务。
- 核心词/同义词支持顿号、逗号和换行分隔；每个词都是独立搜索项，不再拼成一条搜索语句。
- 新增“关键词组”管理页，支持新建、编辑、删除、平台归属、版本化保存和逐词预览。
- 新建采集任务已接入关键词组下拉选择；任务创建时保存关键词快照，后续按关键词顺序逐个搜索。
- 新建采集任务弹窗已提供“新建关键词组”和“管理词组”入口，保存后自动刷新当前任务的关键词组下拉框；左侧管理页继续保留。
- 任务目标数量按“每个关键词”计算；全部关键词搜索结束后，所有作品统一进入详情采集，并按账号均分。
- 新增 `task_search_queries` 和 `videos.search_query`，记录每个关键词的目标、状态、新增数、重复数及作品来源。

### 用户主档评分

- 保留原有意向评分作为默认路径。
- 新增可显式启用的 0–100 分规则评分器，支持购买/咨询、地区、问题明确度、联系方式倾向、重复互动和负向词。
- 每条评分返回命中原因，并写入评分历史；支持规则版本。
- 新增用户身份操作审计表，为后续人工合并/拆分提供数据基础。

### 账号安全、健康和备份基础

- 新增账号限额、工作时段、最小操作间隔和连续失败暂停规则。
- 账号管理页新增“安全规则”，可按账号配置每小时采集上限、每日回复上限、操作间隔、工作时段和连续失败暂停阈值；保存过程在后台执行。
- 调度器在每次采集动作前执行账号安全预检，触发限制时停止当前账号并写入 `[safety]` 日志，不影响其它账号。
- 新增平台健康事件记录；设置页新增四平台基础健康诊断，检查本地采集/回复适配器及账号绑定，并将结果写入 `health_events`。
- 设置页新增“真实浏览器诊断”：按已绑定账号选择对应平台页面，并在每次检测前强制导航到该平台初始页，清理上一次测试遗留的作品页、评论页或回复弹窗状态；随后检查平台地址、登录提示、验证码迹象、搜索入口、评论区、回复控件和上下滚轮。滚轮探测结束后恢复原位置，不进入作品、不点击、不输入、不发送。
- 平台首页诊断已按页面类型区分：小红书探索首页没有评论区或通用输入框时，只要平台地址、登录状态、验证码和滚轮正常，不再误报为异常；搜索结果页/作品页仍继续检查对应内容结构。
- 真实浏览器诊断结果按平台/账号写入健康事件，状态区分正常、需检查、需登录、需人工和异常。
- 设置页增加逐平台/逐账号“查看详情”，展示登录、验证码、搜索、评论、回复和滚轮等检查项；真实诊断会保存仅供排障使用的模糊截图。
- 设置页增加“一键导出诊断包”，将最近健康事件和日志脱敏后打包为 ZIP；账号名/窗口标识哈希化，Cookie、Token、API Key、CDP 地址和 URL 敏感参数不导出。
- 设置页增加“一键深度诊断”：按平台从本地评论数据随机抽取作品/评论，复用正式回复适配器执行打开作品、定位评论、点击回复和填入测试文本，明确停在发送前。
- 深度诊断默认 `confirm=False`，结果记录为“只填不发”；没有采集数据时不打开浏览器，显示“暂无测试数据，未执行”，并支持手动输入作品地址、昵称和评论原文。
- 评论采集改为持续读取平台实际能加载的全部一级评论和楼中回复：抖音取消半年过滤，小红书取消 60 条截断，微博/B站扩大异常页面安全上限；正常结束只依赖平台“没有更多”提示或连续无新增，仍按平台字段去重。
- 抖音图文笔记深度诊断会先点击右侧“评论”面板，再定位评论和回复输入框。
- B站深度诊断优先选择一级评论；若本地样本只有楼中回复，会明确显示“未执行及原因”，不再把评论关系不适配误报成定位失败；采集的楼中回复仍会保留。
- 新增 SQLite 在线备份、校验、SHA-256 记录。

### 设置与 BitBrowser 连接诊断

- 左侧新增“设置”页，并与现有主页面一样在启动阶段预加载，切换时只做页面层级切换。
- 支持配置 BitBrowser 本地 API 地址和请求超时，保存后立即更新当前客户端、调度器和浏览器回复适配器。
- 支持只读检测 BitBrowser 服务，列出窗口名称、窗口 ID、进程号、调试端口和打开状态；不会因检测而打开或关闭窗口。
- 支持保存后续智能回复/评论分析所需的服务商、API 地址、API Key 和模型名称；默认关闭调用，API Key 不写入运行日志。
- API 配置区新增“检测 API 连通性”：使用只读的 OpenAI 兼容 `/models` 请求验证地址、网络和鉴权，不生成回复、不分析评论、不产生模型调用内容；API 保存与 BitBrowser 连接设置已分离，避免出现误导性的 BitBrowser 应用日志。
- API 配置区新增“API 功能测试”：可随机读取本地评论或手动修改测试原文，调用模型进行评论意向分析和完整回复草稿生成；结果只显示在测试面板，不写入互动中心、不输入浏览器、不发送。
- 意向分析支持单次最多 500 条评论批量提交，按编号返回意向、需求和判断依据；API 测试面板暂不启用智能回复调用，正式回复继续使用模板化话术。
- 已适配 DeepSeek V4/Command Code 的思维模式参数：批量意向请求使用 `thinking.type=disabled`，避免 500 条评论先输出大段思维链后耗尽结果额度。
- 回复草稿会拆分模型 `<think>` 思维链与最终回复：思维链仅在测试面板标注展示，正式回复文本自动清除思维链（含未闭合标签），只保留可回复内容。
- BitBrowser 检测增加本地服务、窗口列表、调试端口和浏览器进程四项分项诊断，设置页直接显示状态、说明和耗时。
